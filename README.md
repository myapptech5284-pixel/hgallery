# نظام معرض حور — للأدوات المنزلية والمكتبية

نظام نقاط بيع ومبيعات سطح مكتب يعمل بالكامل محلياً على Windows (Electron + Node + Express + SQLite عبر sql.js).
كل البيانات تُحفظ في ملف واحد على جهاز المستخدم، ولا يحتاج النظام إلى إنترنت بعد التثبيت.

---

## النسخة الحالية

**v5.1.6 + تحديث سجل العميل الشامل وفصل تبويب الموردين**

### أبرز ما أضيف في هذا التحديث

- **سجل العميل الشامل** — لكل عميل سجل كامل يفتح من دليل العملاء، ويضم:
  - كشف حساب زمني يجمع كل الفواتير والسدّدات والمرتجعات برصيد متحرك
  - كل فواتير البيع مع أصنافها وتكلفتها المخزّنة وربحها
  - **فواتير التقسيط مع سجل دفعاتها، مع إمكانية السداد من داخل السجل مباشرة** دون مغادرة الشاشة
  - كل المرتجعات والاستردادات
  - بطاقات مؤشرات: إجمالي الفواتير، صافي المشتريات، المسدد، المستحق، الأقساط المتبقية، صافي الربح
- **فصل العملاء عن الموردين** — تبويبان مستقلان في الشريط العلوي، لكل واحد شاشته ولوحة أرقامه
- **سجل المورد** — كشف حساب على جانب الشراء (توريدات ومرتجعات) + كل حركات التوريد

### كيف تُربط الفواتير بالعملاء

جداول البيع (`invoices`, `installments`) لا تحمل مفتاحاً أجنبياً للعميل، بل الاسم ورقم الهاتف
المكتوبين يدوياً عند البيع. لذلك تعتمد كل عمليات المطابقة **رقم الهاتف أولاً** مع تطبيع الصيغ
(`0101…` = `+20101…` = `0020 101…`)، وتستخدم الاسم كبديل للفواتير النقدية بلا هاتف.

إذا كان هناك أكثر من عميل مسجّل بنفس الاسم، يتجاهل النظام الفواتير بلا هاتف بدل تخمين خاطئ،
ويعرض تنبيهاً واضحاً داخل السجل.

## المتطلبات

| الأداة | الإصدار |
|---|---|
| Node.js | 18 أو أحدث (اختُبر على 24.20 LTS) |
| Windows | 10 / 11 (64-bit) |
| للبناء فقط | .NET Framework 4 (لترجمة غلاف 7za — موجود افتراضياً في ويندوز) |

## التشغيل والتطوير

```bash
npm install
npm run build        # بناء الواجهة + الخادم
npm start            # تشغيل الخادم على http://localhost:3000
npm test             # اختبارات الوحدة
npm run lint         # فحص الأنواع
```

### بناء مثبّت Windows

```bash
npm install
node build/restore-binaries.mjs   # استعادة أيقونة التطبيق (مرة واحدة بعد الاستنساخ)
npm run electron:build            # ينتج dist-installer-v40f/HawrGallery-Setup.exe
```

> **ملاحظة عن بناء المثبّت:** يفك `electron-builder` أداة `winCodeSign` التي تحتوي روابط رمزية
> خاصة بـ macOS، وهو ما يفشل على ويندوز دون «وضع المطوّر» أو صلاحيات مدير
> (`Cannot create symbolic link: A required privilege is not held by the client`).
> سكربت `build/7za-wrapper-build.ps1` يترجم غلافاً صغيراً يحلّ المشكلة، و`npm run electron:build`
> يشغّله تلقائياً قبل البناء.

## بنية المشروع

```
server.ts                 خادم Express: الفواتير، الأقساط، العملاء، الموردون، التقارير
electron-main.cjs         نافذة التطبيق وإدارة نسخ قاعدة البيانات
src/
  types.ts                أنواع البيانات
  services/api.ts         عميل الـ API
  server/db.ts            المخطط وترحيل قاعدة البيانات (sql.js)
  hooks/                  اختصارات النماذج
  components/             شاشات التطبيق
    CustomersScreen.tsx           دليل العملاء (أرقام أعمال + فتح السجل)
    CustomerLedgerModal.tsx       السجل الشامل: كشف حساب + فواتير + تقسيط + مرتجعات
    SuppliersScreen.tsx           دليل الموردين
    SupplierLedgerModal.tsx       سجل المورد: توريدات ومرتجعات
    InstallmentPaymentModal.tsx   نموذج السداد (مشترك بين تبويب الأقساط وسجل العميل)
    Header.tsx                    شريط التبويبات
build/                    سكربتات البناء والأيقونة
```

## الملفات الثنائية

يستطيع GitHub استقبال النصوص فقط عبر الاتصال البرمجي، لذا تُحفظ أيقونة التطبيق
(`build/icon.ico` و `build/icon.png`) بصيغة base64 في `build/icon.ico.b64` و `build/icon.png.b64`.

استعدها بأمر واحد بعد الاستنساخ:

```bash
node build/restore-binaries.mjs
```
